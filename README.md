# 五子棋 AI 博弈引擎

> 15×15 五子棋 AI，纯 Python 标准库实现（零第三方依赖）。
> 算法核心：Negamax + Alpha-Beta 剪枝 + PVS + 迭代加深 + Zobrist 置换表 + VCF/VCT 威胁空间搜索。

一个可玩的五子棋 AI：支持**人机对战**、**AI 自对弈观战**、**三档难度**与**胜率标定**。

## 算法架构

```
engine.decide()  每次走棋按固定顺序判断，命中即返回：
  ① 我方能一步成五        find_winning_move()
  ② 对手能一步成五（必堵）  find_blocking_moves()
  ③ 能否连续冲四取胜        find_vcf()            ← 威胁空间搜索
  ④ 能否一手造双威胁        vct_check()           ← 四四 / 四三 / 双活三
  ⑤ 对手已有活三（必防）    open_four_points()
  ⑥ 以上都没有 → 搜索      iterative_deepening()
                              └ alphabeta → quiesce → linear_eval
```

### 三个关键技术点

**1. 成五点集与威胁分级**

对落点 `p` 与颜色 `c`，定义 `W(p,c)` = 「c 在 p 落子后，再落一子即五连」的空点集合。
用 `|W|` 的基数区分威胁等级，不依赖棋型字符串匹配：

| 等级 | 判据 | 分值 |
|---|---|---|
| 成五 | 落子后已五连 | 10,000,000 |
| 活四 | `|W| ≥ 2` | 1,000,000 |
| 冲四 | `|W| = 1` | 100,000 |
| 活三 | 某方向存在 q，落 q 后 `|W| ≥ 2` | 10,000 |
| 眠三 | 某方向存在 q，落 q 后 `|W| = 1` | 1,000 |

分值**每级差 10 倍**，保证「一个高等级威胁 > 任意多个低等级威胁」。

**2. 威胁必须按方向计数**

一个活三的两个端点都能成活四。若按「点」统计，会把同一个活三误判成「双活三 = 必胜」，
导致 AI 以为自己在赢而放弃防守——表现为「对手连了三子它却视而不见」。
因此 `is_double_threat()` 按 4 个方向分别计数，一个方向最多贡献一个威胁。

**3. 线模式分值增量维护**

叶节点估值原本要扫全盘 72 条线（横 15 + 竖 15 + 两斜各 21），每次约 800 次窗口比较。
改为给每条线缓存分值，落子时只重算经过该点的 **4 条线**（减旧值 → 改内容 → 加新值），
叶节点估值降为 **O(1)**，同等时限下搜索深度提升约 1 倍。

## 快速开始

```bash
# 浏览器对弈（自动打开 http://127.0.0.1:8765）
python gomoku/web.py

# 终端对弈：输入 A7 或 "7 6" 落子
python gomoku/play.py
python gomoku/play.py --level impossible

# 自对弈评测
python gomoku/arena.py --games 20

# 三档胜率标定
python gomoku/rates.py --games 20 --level all
```

> 需要 Python 3.8+，无需安装任何第三方包。

## 实测数据

### 决策开销（Python 3.12，开局阶段）

| 难度 | 每手时限 | 实际完成深度 | 搜索节点 | 耗时 |
|---|---|---|---|---|
| 普通 | 0.15 s | 2 层 | 739 | 138 ms |
| 进阶 | 0.95 s | 3 层 | 5,805 | 864 ms |
| 不可能 | 3.00 s | 4 层 | 7,943 | 2,712 ms |

### 难度标定（对手为「普通人代理」，黑白交替，slip=0.20）

| 难度 | 局数 | 人类胜率 | AI 胜率 |
|---|---|---|---|
| 普通 | 24 | 56.2% | 43.8% |
| 进阶 | 12 | 33.3% | 66.7% |
| 不可能 | 8 | 12.5% | 87.5% |

> 标定基准是脚本代理（会堵五、抢活四、防活三，但有 20% 概率走随手棋），并非真人；
> 真实业余玩家算力弱于该代理，因此实际胜率会更偏向 AI。

## 设计文档

- [`report/algorithm-design.md`](report/algorithm-design.md)：问题形式化、估值推导、两套候选方案对比、
  Alpha-Beta 节点数证明、置换表误命中分析、VCF 可靠性论证、难度设计

要点摘录：

- **为什么候选点只看棋子周围 2 格**：一步成五只需 1 格（五连连续），而「造冲四」最远需要 2 格
  （如 `XXX.X` 的补点），取 2 恰好覆盖两类强制着法，取 4 只会徒增分支
- **为什么 Alpha-Beta 能加速**：剪掉的是「已证明不会改变上层选择」的分支，理想情况节点数
  由 `b^d` 降为 `b^⌈d/2⌉ + b^⌊d/2⌋ − 1`
- **VCF 的可靠性**：连续冲四时对手每步只有唯一合法应手，找到的序列一定必胜；
  但不完备——找不到不代表不能赢

## 已知不足

1. **Python 性能受限**：同等 1 秒内深度只到 3–4 层，换 C++ 可到 8–10 层
2. **开局偏弱**：搜索型 AI 在空旷局面缺乏棋理，开局选点不够讲究
3. **估值表手工标定**：分值量级差一档，行为会从稳健变为冒进
